# Erebos: Provider Abstraction Architecture

**Purpose:** Document how Erebos achieves model-agnostic LLM interaction through provider abstraction

**Status:** Implementation exists on G700, documentation in progress

------

## Core Principle

Erebos doesn't care *what* LLM you're using - it cares about:

- Can I reach it?
- What models does it have?
- What are its resource requirements?
- How do I route requests to it?

This is achieved through **nodules** - pluggable provider clients that implement a common interface.

------

## Nodule Architecture

### What is a Nodule?

A nodule is a generic node that can server any purpose.

A nodule can be configured as an LLM backend provider with:

- **Type**: `ollama`, `anthropic`, `google`, etc.
- **Location**: `localhost`, `network`, or `cloud`
- **Priority**: Routing preference (1=highest)
- **Base URL/API Key**: Connection config
- **Capabilities**: Available models, VRAM, etc.

### Privacy Tiers

**Tier 1: [Localhost](http://Localhost)** (highest privacy)

- Data never leaves single machine
- Example: Ollama running on same device
- Latency: ~50ms

**Tier 2: Network-Local** (high privacy)

- Data stays on your LAN/VPN
- Example: Ollama on P71 @ 192.168.12.100
- No internet required
- Latency: ~100-200ms

**Tier 3: Cloud APIs** (standard privacy)

- Data sent to cloud providers
- Example: Claude API, Gemini API
- Subject to provider ToS
- Latency: ~500-2000ms

## Provider Client Pattern

### Interface Contract

All provider clients implement:

```python
class ProviderClient:
    def __init__(self, **config):
        self.event_emitter = None  # Optional event system integration
    
    def chat(self, model: str, prompt: str, **kwargs) -> str:
        """Send chat request, return response"""
        tool_name = f"{self.provider}:{model}"
        tool_family = self.provider
        
        try:
            response = self._make_request(model, prompt, **kwargs)
            
            # Emit success event (if event system attached)
            if self.event_emitter:
                self.event_emitter.tool_succeeded(tool_name, tool_family)
            
            return response
        except Exception as e:
            # Emit failure event
            if self.event_emitter:
                self.event_emitter.tool_failed(
                    tool_name=tool_name,
                    tool_family=tool_family,
                    error_type=type(e).__name__,
                    error_message=str(e)
                )
            raise
    
    def list_models(self) -> list:
        """Get available models from this provider"""
        raise NotImplementedError
```

## Configuration System

### Primary Config Location

`~/.config/erebos/config.json` (or `.yaml`)

**Current Implementation:** JSON (auto-generated by discovery)

**Future:** Support both JSON and YAML

### Config Schema

```yaml
# Erebos Configuration
# Multiple nodules can be defined
# Routing happens based on: availability, priority, model requirements

nodules:
  # Network Ollama on Desktop (RTX 4090, 24GB VRAM)
  ollama-desktop:
    type: ollama
    base_url: "<http://192.168.12.50:11434>"
    location: network
    label: "Desktop - RTX 4090 (24GB VRAM)"
    priority: 1
    enabled: true
    capabilities:
      vram_gb: 24
      models:
        - llama3.2:70b
        - qwen2.5:72b
  
  # Network Ollama on P71 (P3000, 6GB VRAM)
  ollama-p71:
    type: ollama
    base_url: "<http://192.168.12.100:11434>"
    location: network
    label: "P71 - P3000 (6GB VRAM)"
    priority: 2
    enabled: true
    capabilities:
      vram_gb: 6
      models:
        - llama3.2
        - mistral
        - codellama
  
  # Cloud fallback (disabled for testing)
  claude-api:
    type: anthropic
    api_key: ${ANTHROPIC_API_KEY}
    location: cloud
    priority: 3
    enabled: false

# Discovery settings (mDNS/polling)
discovery:
  enabled: true
  method: mDNS  # Primary: mDNS/Avahi, fallback: polling
  polling_fallback: true
  subnets:
    - "192.168.12.0/24"
  timeout: 5

# Privacy routing
privacy:
  default_tier: network  # Prefer network-local
  allow_cloud: false     # Strict network-only for testing
  pii_detection: true    # Future: content analysis for routing
```

## Routing Logic

### Model-Based Routing

Erebos routes based on model name:

```python
def route_request(self, model: str, prompt: str):
    # Extract provider from model name
    if model.startswith("claude-"):
        provider = "anthropic"
    elif model.startswith("gemini-"):
        provider = "google"
    else:
        provider = "ollama"  # Default assumption
    
    # Find best nodule for this provider
    nodule = self.select_nodule(provider, model)
    
    # Route request
    return nodule.chat(model, prompt)
```

### VRAM-Based Auto-Selection

For Ollama models, route based on requirements:

```python
def select_ollama_nodule(self, model: str):
    requirements = self.get_model_requirements(model)
    
    # Large models (70B+) need 24GB+ VRAM
    if requirements['vram_gb'] > 20:
        return self.nodules['ollama-desktop']  # 24GB
    
    # Medium models (7B-13B) need 6GB+ VRAM
    elif requirements['vram_gb'] > 4:
        return self.nodules['ollama-p71']  # 6GB
    
    # Small models can run anywhere
    else:
        return self.get_highest_priority_nodule('ollama')
```

### Priority-Based Fallback

If preferred nodule unavailable:

```python
1. Try priority 1 nodule
2. If offline/unavailable → try priority 2
3. If still failing → try priority 3
4. If all fail → error (no cloud fallback if disabled)
```

### Privacy-Aware Routing

**Future feature:** Content analysis determines max allowed tier

```python
def analyze_privacy_requirements(self, prompt: str) -> str:
    if detect_pii(prompt) or detect_confidential(prompt):
        return "localhost"  # Never leave machine
    elif detect_sensitive(prompt):
        return "network"    # Stay on LAN
```

## Hook Integration

### Event System Attachment

Providers emit events through `EventEmitter`:

**Success Events:**

- `tool_succeeded(tool_name, tool_family)`
- Triggers: Response received successfully
- Data: Response time, token count (if available)

**Failure Events:**

- `tool_failed(tool_name, tool_family, error_type, error_message)`
- Triggers: Connection error, timeout, API error
- Data: Error details for debugging

### Provider-Agnostic Hooks

Hooks don't care about provider details:

**Session-End Hook:**

- Fires on: Session boundary detected
- Action: Write session summary
- Works for: All providers

**Failure Tracker Hook:**

- Fires on: Consecutive failures (3+)
- Action: Auto-load tool, switch nodule
- Works for: All providers

**Token Monitor Hook:**

- Fires on: Usage thresholds (60%, 80%, 85%, 90%)
- Action: Warn user, suggest compaction
- Works for: Claude, Gemini (token-limited models)
- N/A for: Ollama (no token limits)

### Provider-Specific Hook Behavior

Some hooks adapt to provider context:

```python
class AutoCompactHook:
    def execute(self, event, context):
        # Only relevant for token-limited providers
        if context.provider in ["anthropic", "google"]:
            if context.token_usage > 0.6 * context.token_limit:
                self.suggest_compaction()
        # Ollama has no token limits - skip
```

## Discovery System

### Network Discovery (Current Implementation)

**Primary Method:** mDNS/Avahi service discovery

**Fallback Method:** HTTP polling

**Polling Implementation:**

```python
def discover_ollama_instances(subnet: str) -> list:
    """Scan subnet for Ollama instances"""
    instances = []
    
    # Expand subnet to individual IPs
    for ip in expand_subnet(subnet):  # e.g., 192.168.12.0/24
        try:
            response = requests.get(
                f"http://{ip}:11434/api/tags",
                timeout=1
            )
            if response.status_code == 200:
                models = [m["name"] for m in response.json()["models"]]
                instances.append({
                    "ip": ip,
                    "url": f"http://{ip}:11434",
                    "models": models
                })
        except:
            pass  # Not an Ollama instance
    
    return instances
```

**Usage:**

```bash
# Discovery via CLI
erebos discover --subnet 192.168.12.0/24 --save

# Output:
Found Ollama instances:
  - Desktop (192.168.12.50:11434)
    Models: llama3.2:70b, qwen2.5:72b
  - P71 (192.168.12.100:11434)
    Models: llama3.2, mistral, codellama

Saved to: ~/.config/native-claude-client/config.json
```

## Multi-Provider Fallback

**Status:** Architecture supports it, implementation TBD (code on G700)

**Concept:**

```python
provider_chain = [
    ClaudeClient(api_key=...),     # Try cloud first
    OllamaClient("192.168.12.50"),  # Fall back to network
    OllamaClient("localhost"),      # Fall back to local
]

for provider in provider_chain:
    try:
        return provider.chat(model, prompt)
    except ProviderUnavailable:
        continue  # Try next

raise AllProvidersUnavailable()
```

**Use Cases:**

- Working from laptop at coffee shop (no VPN)
- Claude API down (fall back to local Ollama)
- Network Ollama offline (fall back to cloud)
